# Tacticus Guild War Tracker

Static site tracking guild war results for "Les Joyeux Psychopathes !" across multiple wars, generated from captured `game-event/game3` activity logs (see mitmproxy capture setup in project notes).

## Structure

- `data/wars/<slug>.json` — raw captured activity log for one war
- `data/wars/<slug>.maps.yaml` — that war's zone→map assignment (hard = +2pts/battle, easy = +0.5pt/battle) plus, when read from the game save, the `boards:` block (every zone's boardId); generated by `scripts/read_maps.py`
- `data/maps.json` + `docs/assets/maps/` — the 15 guild war boards: boardId, English name, image, and which 6 are the tracked hard/easy maps
- `data/units.json` + `docs/assets/units/` — real name + portrait of every character/machine of war seen in a captured defense (`scripts/sync_units.py`)
- `data/rosters/<user_id>.json` — each member's roster from the official Tacticus API (git-ignored, `scripts/fetch_rosters.py`); rendered as the "Joueurs" pages by `scripts/rosters.py`
- `data/progression_costs.json` — the game's cumulative costs (XP per level, ability gold / badges, shards + orbs per star step, rank-up energy per character) behind the raid-meta completion %; refreshed with `scripts/fetch_progression_costs.py` (tacticusdb's public data API)
- `docs/assets/ui/`, `docs/assets/items/`, `docs/assets/res/` — game art used by the Joueurs pages (rarity frames, rank medals, faction crests, star icons, item and relic icons, orbs / XP books / requisition orders). Copied from tacticusdb.com and tacticusplanner.app; the artwork belongs to Snowprint Studios / Games Workshop
- `docs/assets/slots.json` — hand-annotated hex centres (px on the 480x480 art) of the 5 numbered defender slots (`e`) and the 5 white attacker slots (`o`) of each board; used by `placement.js` (click an attack -> map with both lineups). Add an entry when a new board image is imported
- `scripts/ranking.py` — the point formula (win/finish tiers, buffs, map bonus, unused-token count)
- `scripts/generate_site.py` — renders `docs/` (the GitHub Pages source) from everything in `data/wars/`
- `docs/` — generated static site, do not hand-edit

## Regenerating the site

```
python3 scripts/generate_site.py
```

## Adding a new war

The maps and the real battlefield layout come from the game save, which only ever holds the current war
(prep or battle) and is overwritten by the next war's prep as soon as a war ends. So **run
`python3 scripts/snapshot_war.py` at some point during every war** (or schedule it): it stores the
config in `data/snapshots/`, and `read_maps.py` finds it later. Then, whenever you capture the war:

```
python3 scripts/add_war.py <capture.json> <slug> --season N --war N --result win|loss
```

It validates the capture, copies it to `data/wars/<slug>.json`, writes `<slug>.maps.yaml` from the save
(`read_maps.py`), downloads the portraits of any new unit (`sync_units.py`), regenerates the site and
checks the result. Then preview locally (`cd docs && python3 -m http.server`), `git add -A`, commit and push.
Run the steps separately if you prefer: `read_maps.py`, `sync_units.py`, `generate_site.py`.

## Players (rosters)

The API keys stay outside the repo, in `~/.config/tacticus-guildwar/keys.json` (`{"players": [{"name", "user_id", "api_key"}]}`; the `user_id` is what matters, `name` is only a label). To refresh the "Joueurs" pages by hand:

```
python3 scripts/fetch_rosters.py && python3 scripts/generate_site.py
```

`fetch_rosters.py` writes the raw API answers to `data/rosters/` (never the keys; it retries on timeouts, and `--strict` makes it exit 1 if any member failed); `generate_site.py` then builds `docs/joueurs.html` and one `docs/joueurs/<id>.html` per member. New characters need their portrait: `python3 scripts/sync_units.py` (reads the local game files).

### Daily refresh (GitHub Actions)

`.github/workflows/refresh-rosters.yml` does the same every day at 11:00 UTC (noon in winter) and can be started by hand (`gh workflow run refresh-rosters.yml --repo alvajp/gw`). The keys come from the repository secret `ROSTER_KEYS` (the content of `keys.json`), are written to a temporary file on the runner and deleted right after; they are never in the repo, the logs or the site. If any member fails after 3 attempts nothing is published. It only refreshes rosters: wars and unit portraits stay manual. The workflow pushes to `main`, so `git pull --rebase` before pushing.

To add or replace a key: edit `keys.json`, then `gh secret set ROSTER_KEYS --repo alvajp/gw < ~/.config/tacticus-guildwar/keys.json` (replaces the whole secret). Never paste a key anywhere else.

### Raid metas

Each player page opens with the raid metas (Lavistodes, Neuro, Battlesuit, Méchas). They come from the Google Sheet "Feuille d'armée JP" > "metas par boss" (snapshot in `data/metas_sheet.txt`, read by `load_sheet()` in `scripts/rosters.py`; the same sheet lists which units each boss needs, which gives the Boss columns of `joueurs.html`, toggled with Metas / Bosses / Primes above the list; units typed "Niche" in the sheet are left out of the Metas view and the player pages and only count for the bosses and primes): per unit its requirement (ability levels, stars, rank, optional relic level; machines of war: abilities and the stars that set their mythic ability). The completion % of a unit is the share of resources already spent (stars / level + rank / abilities, a third each; a required relic takes 10 %), measured with `data/progression_costs.json`; Core / Flex are the mean of their units (machines of war sit in Core or Flex like in the source Google Sheet "metas par boss"). The "Méthodologie" dialog on the site explains it with worked examples; the list on `joueurs.html` can be sorted by meta.

### Menu

Two rows (a third one on the war season, war and strategy pages: that season's wars), dark theme only. First row: Raid, War, Joueurs. The second row appears on the Raid pages (Records, then the raid seasons, latest first) and on the War pages (Stratégie, Défenses, then the war seasons, latest first); both rows scroll sideways on a phone. The War page is `war.html` (`index.html` only redirects to it). Season pages hold the table first, the points scale under it, then the Scores chart.

### Strategy and Défenses pages

`strategie.html` has guild chips (Bloody Rose by default) that filter the "Contre les meilleurs" map and the attack tables under each map (one pill per player, like on the war strategy pages); the guilds are the `COMBINED_OPPONENTS` of `generate_site.py`. `defenses.html` lists, for every map, the best defences seen over all captured wars.

### Medals

Each player page shows medals built with the Onslaught badge art (`docs/assets/ui/onslaught_*.png`, boss portraits in `docs/assets/bosses/`), `scripts/medals.py`: the five members with the best all-time relative damage on each raid boss and sub-boss (every season from 97 on and every difficulty; the same relative damage as the raid ranking, see below) (orange / teal / gold / grey / brown for 1st to 5th; the grey and brown frames are the gold one recoloured), in two lines (bosses, then primes) next to the War and Raid insignias. Every medal is shown on every page, greyed out when not earned. The raid history comes from `python3 scripts/fetch_raid.py` (guild key, `"Guild": {"api_key": ...}` in `keys.json`; raw data in the git-ignored `data/raid/`); the daily workflow fetches it too and publishes nothing if it fails.

### Raid ranking

The Raid insignia (`scripts/medals.py`, `raid_ranking`) works season by season on the raid history (seasons 100 on). Only attacks from Legendary 4 up count (`MIN_LEGENDARY_SET` in `scripts/medals.py`: a season has 5 Legendary bosses, the API's `set` 0-4 in the order they are fought, and 3 Mythic ones, so it is the 4th and 5th Legendary bosses and every Mythic one; the API's `tier` is only the loop count). Bombs and finishing blows are left out; every other attack (one token, one-shots included) is compared with the guild's average hit on the same boss or sub-boss and difficulty tier that season, which gives the relative damage per token (% above the guild average). A player's season score is the mean over their attacks (no minimum), then cut for the tokens they did not play: a season counts 27 tokens (`TOKENS_PER_SEASON`; every attack that is not a bomb is a token), each token short of 27 is a "lost token" and removes 1/27 of the damage, i.e. the score becomes (1 + relative) x tokens / 27 - 1; more than 27 tokens gives no bonus, and a season in progress (nobody at 27 tokens yet) is neither cut nor shows lost tokens. The Raid and season tables have a "Jetons perdus" column, everybody who played the season is ranked on it (former members included), and the insignia shows the member's rank by their Score, the mean of those season scores (lost tokens included; no minimum number of seasons). The guild average is taken over the whole season.

### Raid and Records tabs

`raid.html` ranks the members on the raid ranking above, one column per season (relative damage, % above the guild average), with the seasons in the menu's second row leading to `raid/<season>.html` (everybody who played the season, one column per boss). `records.html` has the podium of every boss and sub-boss; `boss/<key>.html` ranks the members on their all-time relative damage against that boss, one column per season it was fought. Both read `data/raid/` through `scripts/medals.py`.

One-shots: every one-shot counts (a kill from full HP in one attack, at the boss's full HP); only finishing blows (a kill after earlier damage) and bombs are left out.

### Attack dialogs and best attacks

A click on a relative-damage cell of the Raid tables (`raid.html`, `raid/<season>.html`, `records/<boss>.html`) opens a dialog with that player's attacks of the season (on that boss for
a boss cell): level, team, damage, type (Attaque / Finish / OS) and the damage relative to the guild's average hit (same base as the ranking, none for a finishing blow). Only L4, L5
and M1-M3 attacks are kept (`medals.season_attacks`). The attacks are written to `docs/data/raid-<season>.json` (+ `raid-meta.json`) by `generate_site.write_raid_data` and read
by `docs/assets/raid-attacks.js`. Every `metas/<boss>.html` page ends with a table of the 20 best attacks on that boss (relative damage, current members, stored seasons).

### Raid maps

`data/raid_maps.json` gives, per season (only 110-113 so far) and stage (L4, L5, M1, M2, M3), the boards of the first prime, the boss and the second prime (source: the `guild_boss_season_config_<n>` pages
of tacticustable.com; config n = the season's `seasonConfigId`). `scripts/fetch_raid_maps.py` downloads the visuals into `docs/assets/raid-maps/` (512 px WebP). `medals.season_attacks` gives every
attack its board (`encounterIndex` 0 = boss, 1 / 2 = the primes); the maps show in the attack dialogs' header (like the war dialogs), as a column of the best attacks table and as a filter of that
table on the Metas pages. Add a season to the JSON, run the fetch script and regenerate to give that season's attacks a map.

On the war pages that have attack data, a click on any cell of the "Détail" tables except # and Joueur opens the player's attacks of the war in the shared dialog, in the format of the Stratégie page's
attack tables (`docs/assets/war-attacks.js`, reading the page's `#attacks-data` / `#defense-data` blobs); # and Joueur still open the player.

### Player badges

A row of badges sits above the raid medals on each player page (`compute_badges` in `scripts/generate_site.py`, only the earned ones are shown): the biggest / smallest raid bomb of a season (count and
seasons in the tooltip), more than 100 mythic XP books in stock, the five best members of each of the four main metas (mean Core / Flex completion), and the five most reliable, with the highest
war median (ties at the 1600 cap are settled by the average points per war) and most daring in war (mean points of buffs + maps per war). The top-five badges use the Onslaught frames of their
rank, the others a generic dark grey frame; the inside of a badge is empty until there is an asset for it (the meta badges show the meta's icon, the bomb badges their count).
